# Размеченные находки

Классификация из состоявшихся сверок — эталон для пограничных случаев.

## Материальный пробел

**AutoGPT** — `evolyutsiya-agentov` × lanham, гл. 1.3. Раздел про третью волну
рассуждал абстрактно, без единого исторического маркера; источник называет
AutoGPT первой заметной автономной системой, с которой пошел цикл
«план — действие — оценка — перепланирование» — тот самый, что разобран
в первом уроке. *Почему пробел:* именованный якорь к понятию, которое курс
уже преподает, и во всем курсе не встречался ни разу.

**Уровни риска** — `doverie-i-chelovek` × ms, урок 06. Классификация действий
по уровню риска с разным режимом для каждого. *Почему пробел:* процедура
принятия решения, объединяющая точку подтверждения и системные ограничения,
которые урок подавал как два параллельных приема. *Как нашлось:* только при
чтении полного текста источника — первый проход шел по сжатому пересказу,
где этот блок потерялся.

**Несколько источников** — `agentnyy-rag` × illus, гл. 4. Статья целиком
построена на одной базе и одном `search_docs`; источник описывает агентный
поиск как выбор между несколькими базами. *Почему пробел:* отдельная ось
решения («где искать»), а не частный случай переформулировки запроса.

**Разобранный пример** — `promty-osnovy` × lanham, 10.2.1. Источник определяет
цепочку мыслей как примеры, показывающие ход рассуждения. В статье прием
«Примеры» (образец результата) и прием «Рассуждение» (просьба идти по шагам)
были по отдельности, их сочетания не было. *Почему пробел:* рабочая техника
со своей областью применения. *Как нашлось:* при сверке другого узла —
`rassuzhdenie`.

## Украшение

**«USB-C порт для ИИ»** — `mcp` × illus. Яркая метафора для того, что урок
уже объясняет сквозным примером.

**«N×M связей превращаются в N+M»** — `mcp` × illus. Количественная
переформулировка проблемы дублирования, которую урок излагает словами.

**«Билет в один конец» против «билета туда-обратно»** — `multiagent-shablony`
× infante, гл. 12. Метафора для различия маршрутизатора и супервизора;
само различие в статье есть.

**Таксономия оценки по типам приложений** — `otsenka-agentov` × lanham,
11.5.3. Таблица делит оценку по видам продукта (личный ассистент, бот
поддержки, игровой ИИ), а не по механизму. *Важно:* тот же раздел дал
материальный пробел — различение внутренней и внешней оценки. Один раздел
источника может содержать находки обоих классов.

## Ложная тревога

**few-shot** — `promty-osnovy` × infante, гл. 2.5. Поиск по «few-shot»
и «one-shot» не дал ничего, выглядело пробелом. Чтение статьи показало:
раздел «Примеры» покрывает прием целиком, обычными словами.

**Структурированный формат между агентами** — `shablony-proektirovaniya`
× infante, гл. 13. Рекомендация «передавать структурированный формат,
не естественный язык» выглядела отсутствующей; в статье уже стоит
«Свободный текст между агентами — источник половины отказов».

## Не применимо

**Самосогласованность через эмбеддинги** — `metakognitsiya` × lanham, 10.3.
Разбор идет через конкретный инструментарий: подсчет косинусной близости,
YAML-описание потока. Курс работает на уровне механики, а не одного набора
инструментов.

**Защитные ограничители** — Infante, гл. 14. Материал хороший, но целевые
узлы (`bezopasnost-agentov`) на момент сверки были `planned`. Стал применимым,
когда модуль дошел до написания.

**Криптографические детали журнала** — `upravlenie-agentami` × ms, урок 18.
Подписи, канонизация, проверка подписи кодом. В курс пошло понятие —
подписанная цепочка записей и что она доказывает; детали реализации нет.
