### Внешнее (используется с урока 1)

Книга платформо-центрична и не покрывает архитектурный выбор. Эти источники
закрывают дыру и проверены на момент добавления (2026-08-14).

- **[Anthropic. Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)**
  Инженерная статья, ~20 минут. Источник различения workflow / агент, пяти шаблонов
  workflow (цепочка, маршрутизация, параллель, оркестратор-работники,
  критик-исполнитель) и принципа «усложнять только когда это доказуемо улучшает
  результат». Единственный внешний текст, который стоит прочитать целиком на старте.
  Куда за чем: выбор ступени автономии, проектирование инструментов, предупреждения
  про стоимость и накопление ошибок.

- **[Model Context Protocol — введение](https://modelcontextprotocol.io/docs/getting-started/intro)**
  Открытый стандарт подключения ИИ-приложений к внешним системам. Одна страница.
  Использовать, когда дойдем до инструментов: сегодня «дать агенту доступ к календарю»
  обычно означает «подключить MCP-сервер», а не писать интеграцию.

- **[Yao et al. ReAct: Synergizing Reasoning and Acting in Language Models (2022)](https://arxiv.org/abs/2210.03629)**
  arXiv:2210.03629, опубликовано на ICLR 2023. Статья, с которой начался нынешний
  агентный цикл: чередование рассуждения и действия. Книга упоминает ReAct в гл. 10.1
  (с. 374) без разбора — вот первоисточник.

- **[Anthropic — документация по разработке](https://platform.claude.com/docs/)**
  Справочник по Messages API, вызову инструментов, кэшированию контекста и агентным
  циклам. Сюда же за актуальными именами моделей и **ценами** — цены в уроки
  намеренно не вписываю, они меняются.

## Как источник попадает в базу

Содержимое источников в репозитории не лежит: он публичный. Книги и статьи
хранятся в приватном бакете Cloudflare R2 `agenticbase`, а в репозиторий
попадают только оглавления — заголовки разделов и номера страниц.

| Что | Где | Зачем |
|---|---|---|
| PDF как есть | R2, `raw/<id>.pdf` | хранение |
| Извлеченный текст с разметкой страниц | R2, `extracted/<id>.txt` | это читает агент при сверке |
| Оглавление | репозиторий, `sources/outline/<id>.json` | по нему агент выбирает, какие страницы забрать |

Добавление источника — один жест: положить PDF в бакет через панель
Cloudflare. **Имя файла служит идентификатором источника**: `lanham.pdf`
даст источник `lanham`. Допустимы строчные латинские буквы, цифры, дефис
и подчеркивание.

Дальше раз в час работает `.github/workflows/sources.yml`: находит файлы,
для которых оглавления еще нет или которые перезалили, извлекает текст
обратно в R2 и коммитит оглавление. Метка версии файла хранится в поле
`etag` оглавления — по ней видно, что источник заменили и разбор нужно
повторить.

Красный прогон в Actions — это не поломка, а сообщение. Он означает одно
из двух: файл назван не идентификатором, либо источника еще нет в реестре
`sources` манифеста. В обоих случаях текст в логе говорит, что сделать.

Запасной путь, если файл лежит на диске рядом с репозиторием и прописан
в поле `file` манифеста:

```
python sources/sync.py lanham        # разобрать и залить один источник
python sources/sync.py --outline     # только оглавления, без обращения к R2
```

Доступы к R2 берутся из `.env` в корне (файл в `.gitignore`), а в GitHub
Actions — из секретов репозитория `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`,
`R2_SECRET_ACCESS_KEY`, `R2_BUCKET`.

## Журнал сверки

Какие материалы курса с какими источниками реально сверялись — записано
в `kb/manifest.json`, а не держится в голове.

- **`audited` на узле** — даты состоявшихся сверок по каждому источнику.
  Пустой объект означает «под учетом, но ни разу не сверялся». Задним числом
  даты не проставляются: пустота честнее выдуманной даты.
- **`checked_at` на источнике** — дата, на которую подтверждено содержимое
  самого источника. Двигается только при реальном изменении источника
  (у `illus` ранний доступ — при выходе новых глав дату поднять), а не при
  каждом чтении. Сверка считается устаревшей, когда `checked_at` источника
  новее даты в `audited`.

Смотреть состояние:

```
python kb/audit_status.py            # общая картина: что не сверялось, что устарело
python kb/audit_status.py lanham     # план работ по одному источнику
```

Порядок при добавлении нового источника: внести его в реестр `sources`
манифеста, запустить `audit_status.py <id>` — получить план работ, пройти
его по одному узлу, проставляя даты по факту сверки.

## Пробелы

Осознанные дыры, которые 1 курс не закрывает. Каждая — заявка на поиск источника.

1. **Развертывание и эксплуатация в проде.** Книга обрывается на тестировании
   и итерациях версий (гл. 7). Мониторинг, стоимость токенов, деградация качества,
   инциденты — источника нет. Прямо противоречит критерию успеха, закрывать обязательно.
2. **Актуальность платформенного ландшафта.** Гл. 5 и 9 описывают Wenxin, Zhipu Qingyan,
   Kimi+, Tongyi, Kouzi, Tencent Yuanqi — без китайского номера недоступны.
   Практика уходит на Dify, Coze, FastGPT, Claude Code и прямые API.
3. **Code-first фреймворки.** Частично закрыто: Infante дает LangChain/LangGraph/MCP
   с кодом, Lanham — Semantic Kernel и деревья поведения. Держать в уме крен
   в конкретные фреймворки при переписывании — курс остается платформо-независимым,
   код из этих книг не копируется, только идеи и структура.
4. **Экономика и упаковка услуги.** Как оценивать проект, что писать в договор,
   что считать поддержкой — для роли независимого интегратора критично, в книге нет.
