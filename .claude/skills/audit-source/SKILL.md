# Сверка материала с источником

Одна сверка = одна пара «узел курса × источник». На выходе: либо правка
материала, либо обоснованное «пробела нет», и в обоих случаях — дата
в журнале.

## Шаги

### 1. Взять план работ

```
python kb/audit_status.py <источник>
```

Звездочка = источник заявлен у материала, но сверка не подтверждена. Это
первая очередь: там расхождение между тем, на что курс якобы опирается,
и тем, что проверено.

### 2. Прочитать узел целиком

Запись узла в `kb/manifest.json` (`summary` и `concepts` говорят, что узел
считает своей темой) и опубликованный HTML по `path` — весь, а не по
диагонали. Тема узла из шага 2 — фильтр для шага 3.

### 3. Прочитать в источнике все по теме узла

У PDF: `pypdf`, `reader.outline` и `get_destination_page_number` дают карту
глав — по ней выбрать все разделы, относящиеся к теме узла, и извлечь их.
У веб-источника: страница целиком.

Сверка закрывается, **когда прочитаны все разделы источника по теме узла**,
а не первый подходящий. Реальный промах: при сверке статьи про приемы
промпта была прочитана глава 10.2 (техники рассуждения) и пропущена 10.1
(приемы прямого промптинга) — тот же предмет, соседний раздел.

### 4. Сравнить по смыслу

Курс намеренно пишет обычными словами вместо принятых терминов. Поиск по
термину показывает отсутствие слова, а не отсутствие содержания: `few-shot`
живет в курсе как прием «Примеры», контекстная гниль — как «качество падает
до того, как кончится место».

Каждое содержательное утверждение источника получает класс из таблицы ниже.
Прежде чем назвать что-то пробелом — проверить весь курс, а не только
проверяемый узел: `grep` по `articles/`, `lessons/`, `reference/`.

Обещание одного материала про другой («уже разобрано в», «был намек в»)
проверяется на месте: обещанное должно там быть. Реальный случай — урок про
подключение по стандарту ссылался на тезис «в самом конце урока про
инструменты», которого в том уроке не было вовсе. Расхождение чинится
вместе с правкой.

### 5. Классифицировать

| Класс | Признак | Действие |
|---|---|---|
| **Материальный пробел** | Прием, различение или конкретный якорь со своей областью применения, которого нет нигде в курсе | Правка |
| **Не тот узел** | Находка настоящая, но относится к другому материалу | Записать против того узла, к которому относится |
| **Украшение** | Метафора, количественная переформулировка уже объясненного или перечень ярлыков, который сам источник нигде не разворачивает | Пропустить |
| **Ложная тревога** | Термина нет, содержание есть под обычными словами | Пропустить |
| **Не применимо** | Детали конкретного фреймворка или инструмента; целевой узел еще не опубликован | Пропустить |

Разбор пограничных случаев: [`CASES.md`](CASES.md) — размеченные находки
из состоявшихся сверок.

### 6. Внести правку

Держать голос курса: обычный язык, сквозной пример с конкретными данными,
явная плата за прием. Правка встраивается в существующую структуру раздела,
а не пристраивается сбоку.

При вставке нового `<section>` — перенумеровать все последующие
`<span class="num" aria-hidden="true">`. Ссылка из статьи на урок идет как
`../lessons/NNNN-slug`.

### 7. Записать результат

```
python build.py && python kb/check.py
python kb/audit_status.py mark <узел> <источник>
```

Если материал теперь реально опирается на источник — дописать источник
в `sources` узла. Новый прием получает свое понятие в `concepts`.

Дата ставится по факту состоявшейся сверки. Пара с прочитанной наполовину
темой остается незакрытой.

Находка, ушедшая в другой узел, дает правку этому узлу — но не дату: пара
«другой узел × источник» остается открытой, пока источник не прочитан по
его теме. Такую правку описывает коммит, журнал ее не показывает. Это
верная картина: материал улучшен, сверка не проведена.

## Выход

Отчет по каждой находке: класс, обоснование, что сделано. Формулировка
«пробелов нет» указывает, какие разделы источника прочитаны и чем именно
покрыто их содержание в курсе.
