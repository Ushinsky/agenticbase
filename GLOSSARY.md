# Глоссарий курса «Запуск ИИ-агентов»

Канонический язык этого воркспейса. Сюда попадает термин только после того, как
он подтвержден практикой — квизом или разбором задачи, — а не в момент первого
упоминания. Во всех уроках используются именно эти слова.

## Устройство агента

**Агент**:
Система, которая по заданной цели сама выбирает следующий шаг, опираясь на
результат предыдущего, и может изменить поведение после неудачи без участия
человека.
_Избегать_: умный помощник, ИИ-решение, бот с интеллектом

**Такт**:
Один из пяти этапов цикла агента: вход, понимание, решение, действие,
обратная связь.
_Избегать_: стадия, фаза, шаг пайплайна

**Петля**:
Замыкание пятого такта на первый: результат действия становится новым входом.
Ровно то, чего нет у чат-бота и автоматизации.
_Избегать_: цикл обработки, итерация, фидбэк-луп

**Инструмент**:
Внешняя операция, которую модель может запросить по имени с аргументами.
Выполняет ее ваш код, не модель.
_Избегать_: функция, плагин, скилл, интеграция

**Описание инструмента**:
Текст, который модель получает вместо кода: имя, назначение, когда
не использовать, аргументы с форматом и границами, что возвращает. Это все,
что модель знает об инструменте, — не больше и не меньше.
_Избегать_: документация к функции

**Права инструмента**:
Правило допуска для конкретного вызова: выполняется без остановки или требует
подтверждения человеком. Определяется тем, обратимо ли действие, а не тем,
корректны ли аргументы, — это две разные проверки.
_Избегать_: разрешения, доступ

**Контекст**:
Все, что уходит модели на каждом такте: системная инструкция, история разговора,
прошлый опыт, найденные сведения и сам запрос. То, что ощущается как память агента.
_Избегать_: память, история, сессия, промпт (промпт — один слой контекста)

**Слепая зона**:
То, чего нет в контексте. Для агента оно не существует — не «он не учел»,
а «этого не было». Чинится сборкой входа, а не формулировкой промпта.
_Избегать_: агент не заметил, агент забыл, невнимательность модели

## Выбор архитектуры

**Лестница автономии**:
Три ступени, по которым выбирается решение под задачу: одиночный вызов,
workflow, агент. Ступень выбирается самая нижняя из решающих задачу.
_Избегать_: уровни сложности, архитектурные варианты

**Одиночный вызов**:
Один запрос к модели — один ответ. Сюда же относится усиленная модель:
тот же один проход, но с поиском по базе, инструментами или памятью.
_Избегать_: простой запрос, обычный промпт

**Workflow**:
Два и более вызова модели, соединенных вашим кодом по заранее известному
маршруту. Модель решает внутри шага, но не о том, каким будет следующий шаг.
_Избегать_: пайплайн, сценарий, автоматизация, цепочка (это один из шаблонов
workflow, а не синоним)

**Ступень определяется числом решений модели**:
Не числом шагов в системе. Чтение файла, запись в таблицу и цикл по 300
документам — код вокруг вызова; ступень они не поднимают.

## Уточнения, принятые в этом воркспейсе

- **«Агент» никогда не означает «система с языковой моделью внутри».**
  Робот-пылесос — агент без модели; чат с загруженным PDF — не агент при самой
  сильной модели. Решает петля.
- **«Обучение» всегда требует уточнения, какое именно.** Возврат результата
  в контекст текущей работы — происходит постоянно. Дообучение модели —
  в работе интегратора не происходит почти никогда. Употреблять слово
  без уточнения запрещено.
- **Цикл `for` по списку — не петля.** Повторение одного одиночного вызова
  300 раз остается одиночным вызовом. Петля замыкается результатом действия,
  а не следующим элементом списка.
