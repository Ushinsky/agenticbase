# Как устроена публикация

Рабочий цикл: правим файлы, `git push`, через минуту сайт обновлен.
Beget не открывается вообще. Схема:

```
git push -> GitHub Actions -> сборка + проверка -> копирование по SSH -> Beget
```

Если проверка (`kb/check.py`) находит проблему — запрещенную букву,
упоминание источника на публичной странице, битую ссылку, расхождение
манифеста со страницами, — публикация останавливается, на сайт ничего
не попадает. Смотреть результат: вкладка Actions в репозитории.

## Разовая настройка (сделать один раз)

### 1. Собрать данные для подключения

В панели Beget, на главной странице, в блоке "Общая информация" есть
имя сервера. Он же — хост для SSH.

Понадобится четыре значения:

- **хост** — имя сервера из панели, например `serverXX.beget.tech`
- **порт** — обычно `22`, если панель показывает другой, взять его
- **пользователь** — логин от панели управления Beget
- **путь** — куда класть файлы сайта, обычно
  `/var/www/<логин>/public_html` или
  `/var/www/<логин>/data/www/<домен>`. Точный путь показывает панель
  в разделе "Сайты" рядом с доменом ("Директория сайта").

### 2. Сделать отдельный SSH-ключ для этой задачи

Не переиспользовать личный ключ. На своей машине:

```bash
ssh-keygen -t ed25519 -C "agenticbase-deploy" -f ./agenticbase-deploy -N ""
```

Получится два файла: `agenticbase-deploy` (приватный) и
`agenticbase-deploy.pub` (публичный).

### 3. Отдать публичный ключ Beget

В панели Beget: SSH-ключи -> добавить ключ -> вставить содержимое
`agenticbase-deploy.pub`.

### 4. Отдать приватный ключ GitHub

В репозитории: Settings -> Secrets and variables -> Actions ->
New repository secret. Создать четыре секрета:

| Имя | Значение |
|---|---|
| `BEGET_SSH_KEY` | содержимое файла `agenticbase-deploy` целиком, вместе со строками `-----BEGIN...` и `-----END...` |
| `BEGET_HOST` | хост из шага 1 |
| `BEGET_PORT` | порт из шага 1 |
| `BEGET_USER` | пользователь из шага 1 |
| `BEGET_PATH` | путь из шага 1, со слешем на конце, например `/var/www/login/public_html/` |

После этого приватный ключ с диска можно удалить — он больше не
нужен, GitHub хранит свою копию в секретах и никому ее не показывает.

### 5. Проверить

Сделать любой пуш в `main` (или запустить workflow вручную во вкладке
Actions -> Собрать и опубликовать -> Run workflow) и посмотреть на
зеленую галочку. Если шаг "Отправить на Beget по SSH" красный —
разбирать сообщение об ошибке, обычно это неверный путь или порт.

## Три раздела, один портал

Сайт состоит из трех справочных разделов и портальной главной,
которая ведет во все три:

- `kb/` — база знаний (уроки, статьи, рабочие листы). Источник правды —
  `kb/manifest.json`, страница `kb/index.html` собирается
  `kb/build_index.py`. Правила подачи из NOTES.md — без имен продуктов,
  без ссылок на источники — действуют только здесь.
- `news/` — поток новостей. Источник правды — `news/feed.json`,
  страница собирается `news/build_feed.py`. Имена продуктов и ссылки
  на источники здесь не просто разрешены, а обязательны — раздел
  справочный, не учебный.
- `hub/` — каталог конкретных агентов. Источник правды —
  `hub/agents.json`, страница собирается `hub/build_hub.py`. Те же
  правила про имена и ссылки, что в новостях.
- Корневой `index.html` — портальная страница с тремя карточками-входами,
  собирается `build_portal.py` из превью всех трех разделов.

## Что публикуется, а что нет

Наружу уходит все собранные HTML-страницы, `assets/`, содержимое
`lessons/`, `articles/`, `reference/`. Не публикуются: `.git`, `.github`,
`learning-records/` (личные записи), файлы `*.pdf` (источники,
десятки мегабайт, на сайте не нужны), все `*.py` (скрипты сборки) и
три манифеста с данными (`kb/manifest.json`, `news/feed.json`,
`hub/agents.json`) — они рабочие инструменты, а не часть сайта.

## Повседневная работа

```bash
python build.py
python kb/check.py
git add -A
git commit -m "..."
git push
```

`build.py` пересобирает все четыре страницы разом: базу знаний,
новости, хаб и портал — именно в этом порядке, потому что портал
читает превью из трех остальных. Собирать и проверять локально не
обязательно — то же самое сделает Actions при пуше, но так видно
результат до отправки.
